## Description
The MediScript AI application fails to start during the Settings initialization phase. The application worker crashes with Pydantic validation errors indicating that environment variables documented in the project README are not permitted by the Settings class definition.

## Affected Configuration
The following environment variables are affected:
- `OLLAMA_BASE_URL`
- `OLLAMA_MODEL`
- `OCR_ENGINE`
- `TESSERACT_CMD`

These variables are documented in the project README and expected to be configured in the `.env` file, but the current `app/config.py` Settings class does not define these fields, causing Pydantic to reject them as "extra inputs."

## Steps to Reproduce
1. Clone the MediScript AI project repository
2. Create and activate the Python virtual environment
3. Install dependencies from requirements.txt
4. Configure the `.env` file according to the project README documentation
5. Install/pull the required Ollama model (Llama 3.2:3b)
6. Run the Uvicorn command:
   ```bash
   python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
   ```

## Expected Behavior
The application should start successfully and be accessible at port 8001. The Settings class should accept and properly validate the documented environment variables.

## Actual Behavior
The application fails during Settings initialization with four Pydantic `extra_forbidden` validation errors:

```
pydantic_core.ValidationError: 4 validation errors for Settings

1. ollama_base_url
   Extra inputs are not permitted

2. ollama_model
   Extra inputs are not permitted

3. ocr_engine
   Extra inputs are not permitted

4. tesseract_cmd
   Extra inputs are not permitted
```

## Error Traceback
The error occurs during the following call chain:
- `app/main.py` → Application startup
- `app/core/database.py` → Database initialization
- `app/config.py` → Settings instantiation
- `Settings()` → Pydantic validation fails

## Root Cause Analysis
**Status:** COMPLETED

The root cause was identified as a mismatch between:
1. The environment variables documented in the project README (.env file)
2. The actual field definitions in the `app/config.py` Settings class

**Investigation Findings:**
- The `.env` file contained four environment variables (`OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OCR_ENGINE`, `TESSERACT_CMD`) that were not defined in the Settings class
- The application code in `gemma_service.py` was using hardcoded values for Ollama configuration instead of reading from settings
- The application uses RapidAPI for OCR functionality, not Tesseract, so `OCR_ENGINE` and `TESSERACT_CMD` were not actually used by the application
- Pydantic Settings by default rejects extra fields unless explicitly configured otherwise

**Code Analysis:**
- `app/config.py` Settings class was missing the four field definitions
- `app/services/gemma_service.py` had hardcoded `base_url="http://localhost:11434"` and `model="llama3.2:3b"`
- No code in the codebase referenced `OCR_ENGINE` or `TESSERACT_CMD` for actual functionality

## Impact

No workaround was needed. The issue was resolved by adding the missing field definitions to the Settings class.

## Fix Applied
**Files Changed:**
1. `app/config.py` - Added four missing field definitions to Settings class
2. `app/services/gemma_service.py` - Updated to use settings instead of hardcoded values

**Changes Made:**

### 1. app/config.py
Added the following field definitions to the Settings class:
```python
# Ollama configuration
ollama_base_url: str = "http://localhost:11434"
ollama_model: str = "llama3.2:3b"

# OCR configuration
ocr_engine: str = "rapidapi"
tesseract_cmd: Optional[str] = None
```

### 2. app/services/gemma_service.py
Updated the `call_gemma` function to use settings instead of hardcoded values:
```python
# Changed from:
async with httpx.AsyncClient(base_url="http://localhost:11434", timeout=120) as client:
    payload = {
        "model": "llama3.2:3b",
        ...

# To:
async with httpx.AsyncClient(base_url=settings.ollama_base_url, timeout=120) as client:
    payload = {
        "model": settings.ollama_model,
        ...
```

**Rationale:**
- Adding the missing fields allows the documented environment variables to be accepted by Pydantic Settings
- Using defaults ensures backward compatibility if variables are not set in .env
- Updating gemma_service.py to use settings makes the configuration more maintainable and consistent
- The OCR configuration fields are added for future extensibility, though currently unused
