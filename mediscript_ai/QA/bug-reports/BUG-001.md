- **Severity:** High / Blocking

- **Reported By:** QA Team

## Environment
- **OS:** Windows (MSYS_NT-10.0-26200)
- **Python Version:** 3.14
- **Framework:** FastAPI/Uvicorn
- **Configuration Library:** Pydantic Settings
- **AI/ML:** Ollama 0.32.6, Llama 3.2:3b
- **Branch:** qa/testing
- **Test Environment:** Local development environment

## Description
The MediScript AI application fails to start during the Settings initialization phase. The application worker crashes with Pydantic validation errors indicating that environment variables documented in the project README are not permitted by the Settings class definition.

## Affected Configuration
The following environment variables are affected:
- `OLLAMA_BASE_URL`
- `OLLAMA_MODEL`
- `OCR_ENGINE`
- `TESSERACT_CMD`

These variables are documented in the project README and expected to be configured in the `.env` file, but the current `app/config.py` Settings class does not define these fields, causing Pydantic to reject them as "extra inputs."

## Steps to Reproduce
1. Clone the MediScript AI project repository
2. Create and activate the Python virtual environment
3. Install dependencies from requirements.txt
4. Configure the `.env` file according to the project README documentation
5. Install/pull the required Ollama model (Llama 3.2:3b)
6. Run the Uvicorn command:
   ```bash
   python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
   ```

## Expected Behavior
The application should start successfully and be accessible at port 8001. The Settings class should accept and properly validate the documented environment variables.

## Actual Behavior
The application fails during Settings initialization with four Pydantic `extra_forbidden` validation errors:

```
pydantic_core.ValidationError: 4 validation errors for Settings

1. ollama_base_url
   Extra inputs are not permitted

2. ollama_model
   Extra inputs are not permitted

3. ocr_engine
   Extra inputs are not permitted

4. tesseract_cmd
   Extra inputs are not permitted
```

## Error Traceback
The error occurs during the following call chain:
- `app/main.py` → Application startup
- `app/core/database.py` → Database initialization
- `app/config.py` → Settings instantiation
- `Settings()` → Pydantic validation fails

## Root Cause Analysis
**Status:** UNDER INVESTIGATION

The root cause appears to be a mismatch between:
1. The environment variables documented in the project README
2. The actual field definitions in the `app/config.py` Settings class

The Settings class likely needs to be updated to include the missing field definitions, or the Pydantic configuration needs to be adjusted to allow extra fields.
